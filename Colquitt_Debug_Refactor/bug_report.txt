Bug #:        1
Type:         Crash
Line(s):      69
Original:     csv_file.close()
Fixed:        (moved after the for loop, or use "with open(...) as csv_file:")
Symptom:      Selecting Option 1 immediately raised
              ValueError: I/O operation on closed file. No records ever loaded.
Explanation:  csv.DictReader is lazy and reads the file during iteration, not
              when it is created. Closing the handle before the loop leaves the
              reader with nothing to read from, so the file must stay open until
              iteration finishes.

Original:     print(f"  Student ID    : {found_student['Student_ID']}")
Fixed:        print(f"  Student ID    : {found_student['StudentID']}")
Symptom:      Any successful search crashed with KeyError: 'Student_ID'. The
              search only appeared to work when it found nothing.

Bug #:        3
Type:         Logic
Line(s):      22, 89
Original:     csv_loaded = False        (never reassigned after a load)

Bug #:        4
Type:         Logic
Line(s):      71-86
Original:     (the load loop appends without clearing student_records first)
Fixed:        student_records.clear()   (added before the for loop)
Symptom:      Loading the same file twice produced 20 records instead of 10, and
              every record appeared duplicated in the listing.
Explanation:  The list persists between menu selections, so appending without
              clearing accumulates records across loads. Clearing first makes
              each load replace the collection rather than add to it.

Bug #:        7
Type:         Logic
Line(s):      159
Original:     elif menu_choice == 4:
Fixed:        elif menu_choice == "4":
Symptom:      Choosing Option 4 printed "'4' is not a valid option" and the
              program could not be exited through the menu.
Explanation:  input() always returns a string, so comparing it to the integer 4

              "4" matches what the user actually typed.

Bug #:        8
Type:         Logic
Line(s):      25, 133
Original:     found_student = None      (set once at startup, never reset)
Fixed:        found_student = None      (added at the start of each search)
Symptom:      After one successful search, a later search for a nonexistent ID
              reported the previous student as found instead of reporting no
              match.
Explanation:  The variable held its value from the prior search, so the
              "if found_student is None" check passed incorrectly. Resetting it
              before each search makes the result reflect only the current query.

Bug #:        9
Type:         Subtle
Line(s):      135, 138
Original:     while search_index <= len(student_records):
                  ...
                  search_index = len(student_records)  - 1   # Force loop to end
Fixed:        while search_index < len(student_records):
                  ...
                  search_index = len(student_records)        # Force loop to end
Symptom:      Searching for the last record in the file, or for an ID that does
              not exist, crashed with IndexError: list index out of range.
Explanation:  Valid indices run from 0 to len-1, so "<=" allows one index past
              the end. The exit line also stopped one short, which let the loop
              re-check and then step past the final element. Using "<" and
              setting the index to len() exits cleanly in both cases.

-------------------------------------------------------------------------------
Bug #:        10
Type:         Subtle
Line(s):      136
Original:     if student_records[search_index]["StudentID"].upper() == search_id:
Fixed:        if student_records[search_index]["StudentID"].upper() == search_id.upper():
Symptom:      Searching for "s1005" in lowercase reported no match, while
              "S1005" in uppercase worked correctly.
Explanation:  Only the stored ID was uppercased, so the comparison still failed
              whenever the user's input differed in case. Uppercasing both sides
              makes the comparison genuinely case-insensitive.
